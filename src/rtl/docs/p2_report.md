## 3. Verification (L2)
- **Golden values come only from the L1 C library** (`import hwmodel as H`: `fma add sub mul fmax fmin cmp
  i2f exp recip rsqrt sqrt tanh erf log`). `tb/fp/gen_vectors.py` writes inputs and the L1 outputs as hex.
  The testbenches compare every bit (`!==`). They also check that the exact latency is met and that every
  input produces exactly one output; the SFU testbench matches results by tag and has a watchdog. No
  testbench derives an expected value from the RTL or from `real` arithmetic. Fault injection (one
  corrupted expected word) gives `FAIL fma 1/124867`.
- **Directed sets.**
  - add/mul/FMA:
    - a 42-value special set crossed fully (42^3 = 74,088 for FMA): +-0, +-inf, quiet/signalling/negative
      NaNs, the smallest and largest subnormals, 2^-126 and its neighbours, 1 +- ulp, max finite, ...;
    - the FTZ boundary from both sides (2^-126 x (1 - k ulp), (2^-126 + k ulp) x (1 - ulp), with and
      without a cancelling addend);
    - exact half-ulp ties (1 + k 2^-24, few-bit significands);
    - massive cancellation (c = -(a*b) +- 3 ulp, x + (-x +- k ulp));
    - every product/addend exponent offset from -80 to 80 (the alignment shifter);
    - every add exponent difference from 0 to 59;
    - every mul exponent pair summing to the overflow/underflow edge;
    - overflow by rounding.
  - Transcendentals:
    - the special set;
    - +-4 ulps around every branch and range threshold of arith.md, both signs: 89, -104, 9, 1, 3.92,
      0.921875, the ln split 0x3FB504F3, ...;
    - every binade boundary with significands 0, 1, max, max-1, 0x400000, 0x3504F3 and 0x3504F4;
    - **the worst-ulp input of every binade of each function**, found by L1's exhaustive `ulp_scan` per
      binade and per sign. This includes arith.md's recorded worst points.
- **Random sets.** These mix 10 operand families: uniform bit patterns, normals, mid-range values,
  near-1 values, one special or subnormal operand, few-bit (tie) significands, tiny (FTZ) exponents and
  huge (overflow) exponents. One sixth of the FMA vectors and one quarter of the add vectors are forced
  into cancellation. For the SFU: uniform bits, the useful domain, log-uniform normals, and the region
  around the branch points.
- **Icarus smoke** (directed sets): fma STAGES 1/2/3/4/6, add 1-5, mul 1-3, cmp 1-2, i2f 1-3, and SFU at
  LF 1-4 with 1 and LF+2 threads. Each SFU configuration runs the exp and tanh directed sets plus a
  21,000-vector mixed-function stream with input gaps. About 1.3 M vectors in total, 0 mismatches.
- **Gate-level** (`make synth-fp`): the production netlists with the PDK cell models (Verilator) run the
  directed sets, 1 M random vectors per fixed unit, and the mixed SFU stream. 5,278,690 vectors,
  0 mismatches. This check found a real bug during development: `localparam [1:0] NT = 4` truncates to 0
  in Yosys, while Icarus kept 4, so the RTL simulation passed and the netlist was empty. GLS now guards
  against that whole class of bug.
- **Micro-program check** (`make gen-check`): `flow/gen/sfu_ucode.py check` runs every micro-program op by
  op through L1 `fma`, with the same integer pre/post steps, and compares the result with the L1
  functions. 1.4 M inputs, 0 mismatches. This checks the programs before any RTL runs. It is not an L2
  result.
- **L1 additions** (arith.md section 5): `fmin`, `cmp` and `i2f`, with no new numerics. `make
  model-check` still PASSes.

## 4. SFU architecture: micro-sequenced, one FMA per lane
The SFU reuses one FMA under microcode instead of building pipelined datapaths. A pipelined exp alone
would need 13 FMAs, and tanh would need 25. That is 13-25 x 0.10 mm2 per lane, which at V = 16 is
roughly the area of the whole 256-PE array. The vector unit does not need that throughput:
- softmax is the only SFU-bound vector pass. It needs ~150 M exps per step (forward plus backward
  recompute). At 1/13 per cycle per lane x 16 lanes, that costs ~122 M cycles, 4 % of the 3.0 G-cycle step.
- GELU and GELU' run in the GEMM epilogue. The FFN GEMMs deliver one output per lane every ~48 cycles
  (1,024 outputs per K x lambda = 3,072-cycle pass, over 16 lanes). erf takes 24 cycles and erf + exp
  takes 37, so the epilogue stays hidden behind the array.

The barrel design gives the FMA one op per cycle with no hazard logic: T = LF + 2 slots take turns, and
each result is written back before its slot's next turn. Short branches (tanh |x| < 1, erf |x| < 0.921875)
are padded at the front to the long branch's length. That makes the latency fixed per function, which
suits a statically scheduled vector unit. The cost is only in erf's GELU use, where the time is hidden in
the epilogue anyway. Every rounded op is `fma`, because `mul(x, y) = fma(x, y, -0)`,
`add(x, y) = fma(x, 1, y)` and `sub(x, y) = fma(x, 1, -y)` are bit-identical to L1's separate ops
(arith.md section 1). Each algorithm therefore matches arith.md op for op: the same seeds, constants
and Newton/Horner order.

## 5. FMA area vs P0's estimate; budget update
- P0 (budget.md) assumed **171,679 um2** for the lambda = 4 FMA PE.
- Measured: the FMA alone at STAGES = 4 is **119,410 um2**. Adding the 4 x 32 accumulator flops and 100
  operand flops gives a PE of **132,929 um2, -23 %**.
- At STAGES = 2, which closes with +9.6 ns, the FMA is 104,189 um2 and the PE ~113,900 um2.
- The measured SFU is 222,855 um2, against P0's assumed 60,000 um2 plus the lane FMA (~232 k). The two are
  close, but the measured SFU carries its own FMA.

## 6. Deviations and notes for the PI
1. **The FMA closes 40 ns at ss with 2 stages.** D8's lambda = 4 also closes (+16.5 ns) but costs
   +15 k um2 per FMA and twice the accumulators. The parameter stays open. lambda is P3's choice, since
   it sets the GEMM pass geometry (C x lambda columns). budget.py keeps lambda = 4.
2. **fp_add's production setting is STAGES = 2.** 1 stage closes, but with only +2.1 ns pre-layout.
3. **min semantics.** `fmin(a, b) = a > b ? b : a` on DAZ'd operands. It equals dataflow's clip
   `c > 1 ? 1 : c` exactly, NaN included.
4. **SFU area does not shrink with fewer threads.** `NTHR` < T saves no area as built: the contexts are
   still sized T. It is a throughput knob only.
5. The SFU returns results in order only within one function. Mixed functions can reorder, so the SFU
   carries an `in_tag`/`out_tag` (TAGW parameter).
6. **Timing is pre-layout STA on the Yosys netlist** (ideal clock, no wires), as in the tutorial. PnR
   numbers come in P8.

No contract was changed. Every arith.md algorithm was implementable as written.
